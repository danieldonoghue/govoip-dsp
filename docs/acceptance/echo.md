# Acceptance criteria: `echo`

Pre-registered before the implementation, as requirements §9 demands. Changes
after the first implementation commit need a written justification in the
"Changes" section at the end of this file.

## Parity class

**Bit-exact** with SpeexDSP 1.2.1 (commit `1b28a0f6`), FIXED_POINT build,
`USE_KISS_FFT`, no SIMD, `TWO_PATH` (always defined in `mdf.c`), one
microphone and one loudspeaker, compiled by the reference harness with
`-O2 -fwrapv -ffp-contract=off`.

The reference entry points are `speex_echo_state_init`,
`speex_echo_cancellation`, `speex_echo_capture`, `speex_echo_playback`,
`speex_echo_state_reset`, `speex_echo_get_residual` and `speex_echo_ctl`
(`GET_FRAME_SIZE`, `SET_SAMPLING_RATE`, `GET_SAMPLING_RATE`,
`GET_IMPULSE_RESPONSE_SIZE`, `GET_IMPULSE_RESPONSE`). The deprecated
`speex_echo_cancel` is the same as `speex_echo_cancellation` and is not
ported separately. Multichannel (`speex_echo_state_init_mc` with more than
one channel) is stretch item S4 and is out of scope.

For every case below the Go port must give the same:

1. output samples of every cancellation or capture call;
2. residual-echo spectrum (`frame_size + 1` values) after every
   cancellation or capture call;
3. impulse response (`GET_IMPULSE_RESPONSE`) at the end of the case.

## Fixture matrix

Each case is a configuration plus a scenario. The configurations are the
product of:

| Parameter | Values |
|---|---|
| Sampling rate | 8000, 16000, 32000, 48000 Hz |
| Frame size | 10 ms and 20 ms of samples (80 to 960) |
| Filter length | 64, 128 and 256 ms of samples |

That is 24 configurations. Every scenario runs in every configuration,
except the long runs, whose configurations are listed with them. The rate is
set with `SET_SAMPLING_RATE` after `speex_echo_state_init`, as applications
do.

The 32 and 48 kHz rows are included because the reference accepts those
rates. They are compared bit for bit like the others.

## Scenarios (requirements §5.6)

All inputs are generated by the Go test from fixed seeds
(`echo/scenario_test.go`), with `internal/testutil` generators and integer
arithmetic only, and written into the harness input directory. The driver
records every input as a stream, so a generator change shows up as an input
mismatch. The far-end speech and near-end speech are `testutil.SpeechLike`
with different seeds. The echo is the far end convolved, in integer
arithmetic, with a synthetic room response (a dense early part and decaying
sparse reflections, Q15 taps), plus white noise of amplitude 8 on the
microphone unless stated.

| Scenario | Content |
|---|---|
| `farend` | Far-end speech with echo path A (4 ms bulk delay, reflections to 48 ms), no near end, 16 s |
| `nearend` | Far end silent, near-end speech, 12 s |
| `doubletalk` | Far-end speech with path A throughout; near-end speech from 8 to 12 s and from 15 to 18 s, 20 s |
| `silence` | Far end on, off (mic noise only), on, digital silence on both inputs, on; 16 s |
| `lownoise` | Low-level far-end pink noise (peak 200) with path A, mic noise amplitude 4, 16 s |
| `ir_short` | Path with no bulk delay and a 6 ms response, 12 s |
| `ir_long` | Path with 10 ms bulk delay and reflections to 220 ms (longer than the 64 and 128 ms filters), 16 s |
| `path_sudden` | Path A for 10 s, then path B (other seed, 8 ms delay) for 10 s |
| `path_gradual` | Path A until 6 s, linear crossfade to path B from 6 to 14 s, path B to 20 s |
| `misaligned_late` | Path A with an extra bulk delay of the filter length plus 32 ms, so the echo lies outside the model, 16 s |
| `misaligned_early` | The reference passed to the canceller lags the signal that makes the echo by 30 ms (acausal echo), 16 s |
| `diverge` | Normal far end; then a full-scale square far end with a clipping mic; a mic DC offset; the echo path cut while the far end continues; full-range noise on both inputs; normal far end again; 20 s |
| `reset` | `farend`, with `speex_echo_state_reset` called after 8 s |
| `capture` | Buffered mode: `speex_echo_playback` and `speex_echo_capture` driven by a seeded call sequence that starts with playbacks before the first capture and includes captures with no playback frame (underrun) and repeated playbacks (overrun and auto-fill) |
| `rate_switch` | `farend` at the configured rate, with `SET_SAMPLING_RATE` changed to the next listed rate (48 kHz wraps to 8 kHz) after 8 s |
| `edges` | Boundary inputs, added after the first implementation commit (see "Changes"): a far frame whose energy sits exactly on the adaptation threshold, microphone samples of exactly ±32000 and ±31999, microphone samples whose pre-emphasis output is exactly ±32767, then `SET_SAMPLING_RATE` to 12000, 11999, 24000, 23999, 32768, 32767 and back; 16 s |

**Long runs**, compared through SHA-256 chunk hashes of the full streams:

1. 60 s mixed scenario (far end, double talk, silence, path changes, near
   end only, built from 30 s seeded blocks) at every rate, 10 ms frames and
   20 ms frames, 256 ms filter: 8 cases.
2. 10-minute seeded mixed scenario at 8 and 16 kHz, 10 ms frames, 128 ms
   filter: 2 cases.

## Pass criteria

1. Every case matches: committed prefixes element by element, and the
   SHA-256 of every chunk of every stream, including the input streams.
2. The canonical fixtures come from the pinned Linux container
   (linux/arm64, ADR `wp0-reference-build`). The host clang build gives
   identical hashes, or each difference is documented as a finding in
   `docs/testing.md`.
3. The `-fsanitize=undefined` build gives identical outputs to the plain
   build, and its reports in `mdf.c` are listed in `docs/testing.md`. For
   every report on a path that affects output, the Go behaviour on that
   input is shown to equal the canonical reference, or the case is raised
   for a decision.
4. Committed fixtures stay within requirements §4.2: no file above 1 MB, and
   the echo fixtures below 6 MB in total. Long runs commit only a prefix.
5. Under `-short` and `-race` the reference test compares a leading part of
   every case (say so in the test); the full comparison runs in the normal
   `go test`.
6. The driver can write a per-call trace of every state variable of
   `SpeexEchoState`, and the Go test can compare it, so that a mismatch is
   reported as the first differing call and the first differing variable
   (and element, with a full dump of that call).

## API and robustness criteria

1. `New` returns an error, and does not panic, for a frame size whose FFT
   size `2*frame_size` is not supported by `internal/fft`, for a filter
   length that gives fewer than 1 or more blocks than the documented limit,
   and for a sampling rate outside the documented range. Every value the
   reference would divide by zero for is rejected.
2. `Cancel`, `Capture` and `Playback` return `ErrBufferSize`, writing
   nothing and changing no state, for any slice whose length is not the
   frame size, and `Residual` and `ImpulseResponse` for a short slice.
3. No method allocates after `New` (`testutil.AssertNoAllocs`, after
   warm-up past adaptation, including the capture and playback paths).
4. No method panics for any input: a fuzz test drives random
   configurations, call sequences and sample values (including full-scale
   and -32768 runs) without failure.
5. Every division the port makes is listed in the package's design notes
   (`docs/algorithms.md`) with the argument that its divisor is nonzero for
   every input, or with the test that shows the closest boundary. A
   reachable zero divisor is raised for a decision, not guarded silently
   (contracts section 8).
6. Calling `Residual` any number of times does not change any later output:
   every scenario gives identical outputs with and without `Residual`
   calls, and two calls in a row give identical spectra.
7. `Reset` matches `speex_echo_state_reset` (the `reset` scenario). Its doc
   states what it keeps. A test checks that after `Reset` the output equals
   a fresh instance's wherever the reference state allows it, and documents
   the state that the reference does not reset.
8. Long runs show no state growth: all state is allocated in `New`, and the
   10-minute runs match the reference.

## Scenario measurements (sanity and regression)

The bit-exact port defines correctness. These measurements make the
behaviour visible in human terms and catch regressions. They are measured
on the Go implementation, which equals the reference.

Definitions, over 0.5 s windows:

- **ERLE**: `10*log10(sum(mic^2) / sum(out^2))` over windows where the near
  end is silent and the echo at the mic is above -50 dBFS RMS.
- **Steady-state ERLE**: ERLE over the last 4 s of far-end-only activity
  before any later condition change.
- **Convergence time**: the start of the first window, counted from the
  onset of far-end activity, whose ERLE is at least 10 dB. "Not reached"
  is a valid result and is reported.
- **Near-end level change**: `10*log10(sum(out^2) / sum(ref^2))` over
  near-end-only windows, where `ref` is the output of a fresh canceller fed
  the near end alone with a silent far end (so the DC notch and the
  pre-emphasis are not counted).
- **Near-end to residual ratio** in double talk:
  `10*log10(sum(ref^2) / sum((out - ref)^2))` over double-talk windows, with
  `ref` as above, compared with the same ratio for the unprocessed mic
  (`mic - near`).

Every scenario's figures are reported in `docs/algorithms.md` for every
configuration, and the Go test pins them, so a change in behaviour is
visible. Sanity floors, which apply at 8 and 16 kHz only:

1. `farend` and `ir_short`: steady-state ERLE at least 10 dB, and
   convergence within 8 s.
2. `nearend`: near-end level change within ±2 dB.
3. `doubletalk`: the near-end to residual ratio improves on the unprocessed
   mic by at least 3 dB.
4. `diverge`: the run reaches the reference's internal reset (`screwed_up`
   reaching 50) in at least one configuration, so that path is covered.

Other scenarios, and every scenario at 32 and 48 kHz, are reported without a
floor. A floor that fails while the port is bit-exact is a finding about the
reference, reported as such; it is not fixed by changing the
compatibility path.

**Speech**: a LibriSpeech scenario at 16 kHz (one utterance as far end,
another as near end, with path A, far-end-only then double talk) reports the
same figures. It skips when the speech files are absent.

## Documentation criteria

The package doc states rates, frame sizes, filter length and its limit,
chunking, aliasing, retention, `Reset`, concurrency, allocation, and stream
alignment: what echo delay the filter length covers, the capture and
playback ordering rules and the delay of the buffered mode, and what happens
when the echo delay exceeds the model. It does not claim delay estimation.

## Benchmark targets

`Cancel` with 10 ms frames at 8 and 16 kHz with each filter length (64, 128,
256 ms), plus 32 and 48 kHz with the 256 ms filter and 20 ms frames at 16
kHz. Zero allocations per frame. Target: every 10 ms benchmark uses at most
10% of the frame duration on the Apple Silicon reference machine. Results
go into `docs/performance.md`, with the environment.

## Changes

### Scenario `edges` added (after the first implementation commit)

Mutation checks on the implementation found five changes that no input
caught, because no input reached the boundary they move: the microphone
pre-emphasis clamp at ±32767 (`mdf.c:728-739`), the microphone saturation
test at ±32000 (`mdf.c:973`), the far-end energy threshold of the
temporary adaptation rate (`mdf.c:1153`), and the notch-radius rate steps
at 12000 and 24000 Hz (`mdf.c:1241-1246`). The `edges` scenario builds
inputs that sit exactly on each boundary (the generator searches the
sample values with the port's own pre-emphasis, which depends only on the
microphone samples), and `TestEdgesHitBoundaries` checks that they do. It
runs in all 24 configurations like the other scenarios. This widens the
tested domain and relaxes nothing.

### Reference tests run in parallel (WP6b)

WP6b makes the independent reference cases run as parallel subtests, to
cut the wall time of `go test ./echo`. The change touches test files only.
It is accepted when:

1. **Same cases in every mode.** In the normal run, under `-short` and
   under `-race`, the same cases run with the same comparisons as before.
   `go test -v` on `master` and on the branch list the same passed and
   skipped tests and subtests in each mode. A test that gains subtests
   is named here, and its subtests are exactly the cases it ran before.
   The `-race` subset stays as `docs/testing.md` states it.
2. **Comparisons still run.** Swapping `q07` and `q03` in the adaptation
   mask (`mdf.go:668`) is still caught by both reference tests, in the
   normal run and under `-race`. The mutation is reverted afterwards.
3. **No shared mutable state.** Parallel subtests share only data that is
   read-only after it is made, or data behind a lock. The review shows
   this from the code for each parallel test, including the generated
   inputs and every package-level variable they reach.
4. **No new flakiness.** `go test -count=3`, `go test -short -count=3`
   and `go test -race -count=3` of the package pass. The zero-allocation
   tests do not run at the same time as parallel tests.
5. **Measured.** The wall time of `go test`, `go test -short` and
   `go test -race` of the package is measured on the Mac on `master` and
   on the branch, on an otherwise idle machine, and recorded in
   `docs/testing.md` with the date and the core count. There is no
   numeric target; a change that does not reduce the time is reported as
   such.
6. `make check` and `make race` pass.

This changes how the tests are scheduled and relaxes nothing.
